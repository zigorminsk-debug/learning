# Бизнес: школы и практики

Учебник по бизнесу, построенный на **передовых школах** управления и экономической мысли,
и Android-приложение-читалка. Каждое изменение в репозитории автоматически собирается
в подписанный APK средствами GitHub Actions.

## Состав

| Часть | Содержание |
|---|---|
| `textbook/` | Исходники учебника: 22 главы в Markdown (от классики Тейлора до ESG) |
| `app/` | Android-приложение (Kotlin): список глав + чтение в WebView |
| `tools/build_html.py` | Генератор HTML/индекса из Markdown |
| `.github/workflows/build-apk.yml` | CI: сборка → подпись → Release с номером сборки |
| `keystore/` | Постоянный ключ подписи (`release.p12`) и его свойства |

## Сборка APK (GitHub Actions)

Триггер: **push в `main` или в ветку сессии** (и ручной запуск `workflow_dispatch`).

Что делает workflow:

1. Ставит JDK 17, Android SDK, Python.
2. Генерирует HTML глав из Markdown (`tools/build_html.py`).
3. Собирает **подписанный** release-APK через Gradle.
4. Присваивает сборке **номер** = `github.run_number`:
   - `versionCode` = номер сборки,
   - `versionName` = `1.0.<номер>`,
   - имя файла и артефакта = `BusinessTextbook-1.0.<номер>.apk`,
   - тег релиза = `apk-v1.0.<номер>`.
5. Проверяет подпись `apksigner`, публикует **GitHub Release** с APK
   (вкладка *Releases* репозитория) и артефакт прогона.

Номера монотонно растут → APK с более поздней сборкой всегда устанавливается
**поверх предыдущего** (та же подпись, растущий `versionCode`).

## Подпись и обновления

- Ключ: `keystore/release.p12` (**постоянный**, лежит в репозитории намеренно —
  учебный проект; без общего ключа обновления поверх невозможны).
- Свойства ключа: `keystore/keystore.properties` (пароль, alias, тип PKCS#12).
- Релизы подписываются этим же ключом, поэтому **обновление устанавливается поверх**.

> ⚠️ Практическая заметка: ключ, лежащий в открытом репозитории, подходит только
> для учебных/демо-проектов. Для продакшена ключ хранят в секретах CI
> (GitHub Secrets) и не коммитят.

## Локальная сборка

```bash
# 1. Сгенерировать HTML из учебника (нужен Python + pip install markdown)
python3 tools/build_html.py

# 2. Собрать APK (нужны JDK 17 и Android SDK)
./gradlew assembleRelease \
  -PversionCode=1 -PversionName=1.0.0

# Результат: app/build/outputs/apk/release/app-release.apk
```

## Редактирование учебника

1. Правьте главу в `textbook/NN-slug.md` (front matter: `title`, `subtitle`).
2. Запустите `python3 tools/build_html.py` (или просто запушьте — CI сделает генерацию сам).
3. Новая глава = новый файл `textbook/NN-...md`; порядок и номера задаются префиксом `NN`.

## Структура приложения

- `MainActivity` — содержание и хаб:
  - **полнотекстовый поиск** по главам с подсветкой совпадений;
  - закладки (фильтр «Закладки»), случайная глава, прогресс чтения (%);
  - кнопка «Продолжить чтение», переключатель темы, проверка обновлений;
  - **двухпанельный режим на планшетах (sw ≥ 720 dp)**: список слева, читалка справа;
  - сетка 1/2/3 колонки по ширине экрана.
- `ChapterActivity` + `ChapterFragment` — чтение главы:
  - свайп влево/вправо — переход между главами (не мешает прокрутке таблиц);
  - **озвучка главы (TTS)**, экспорт **в PDF**, отправка текста главы;
  - закладка-звёздочка, диалог «Содержание», шрифт **А−/А+**;
  - прогресс чтения сохраняется и показывается в списке;
  - ограничение ширины колонки (780 dp), поворот экрана без потери позиции.
- `widget/RandomTextbookWidget` — виджет «Случайная глава» на рабочем столе.
- `UpdateChecker` — проверка последнего релиза через GitHub API.
- `SearchIndex` + `assets/search_index.json` — индекс (генерируется `tools/build_html.py`).
- `assets/chapters/*.html`, `assets/index.json`, `assets/style.css` — контент.
- Material You (динамические цвета, Android 12+) — `TextbookApp`.

## Тесты и скриншоты UI

`./gradlew testReleaseUnitTest` (Robolectric):

- `ChapterRepositoryTest` — все 22 главы и файлы ассетов на месте;
- `SearchIndexTest` — полнотекстовый поиск и подсветка;
- `UiSmokeTest` — экраны создаются без падений; карточка главы и главный экран
  рендерятся в PNG (`app/build/reports/ui-screenshots/`).

В CI тесты и скриншоты публикуются артефактом `ui-tests-1.0.<номер>` после релиза.
